# 도쿄 여행 일정 웹앱

Henry의 개인 여행용 모바일 웹페이지. 2026년 11월 18일(수)~22일(일), 아카사카 숙소 기준, 문화·예술 컨셉(미술관, 서점, 북카페, LP바). 여행 중 길 위에서 한 손으로 보는 용도가 1순위다. 사용자는 한국어를 쓴다. 모든 UI 문구는 한국어로.

## 현재 상태

- 빌드 과정 없음. 저장소의 이 폴더를 그대로 정적 호스팅하면 된다.
- `index.html` 한 파일에 CSS와 JS가 인라인으로 들어 있다. 디자인은 저장소의 `design-md/` 컬렉션에서 뽑아 왔다(아래 디자인 규칙 참고). 일정 데이터는 `<script>` 안 `/* DATA:START */ … /* DATA:END */` 블록의 `HOTEL`, `DAYS`, `RECS`, `PREP`, `SOS`, `PHRASES`, `NORMALS`, `CHECKS`, `AIRPORTS`, `ARRIVE`, `TRANSIT`, `LOOP` 다.
- 장소 필드: `t`(시간) `n`(이름) `ja`(일본어) `jaTodo`(일본어 미확인) `kc`(종류 키) `k`(종류 표시) `note` `need`(예약 배지) `ask`(확인 필요 배지) `needId`(예약 체크리스트 연결) `doneLabel` `ok`(현장 발권) `cash` `closed`(휴무) `close`(폐관·마감 시각) `tight`(마감 빠듯) `opt`(선택 일정) `leg`(직전 장소에서 오는 방법) `q`(지도 검색어) `id`(Google place_id) `lat` `lng`. 번호(`num`)와 인덱스(`_idx`)는 실행할 때 자동으로 붙는다.
- `kc` 값: `art` `book` `food` `bar` `market` `view` `hotel` `move`. 색은 `--k-*` 토큰, 아이콘은 `#i-*` 심볼.
- **숙소(`HOTEL`)는 SPABLIC INN 아카사카**(かぷせる旅籠赤坂, 東京都港区赤坂3-10-4 赤坂月世界ビル 3F, 35.676047·139.736752)로 확정됐다(2026-09-24, Hotels.com·예약 사이트 기준). 캡슐 호텔이라 체크인 15:00·체크아웃 11:00, 신분증과 카드, 보증금 5,000엔, 짐 보관 가능. 가장 가까운 역은 긴자선·마루노우치선 **赤坂見附(1분)**. 수요일 체크인 카드에는 `HOTEL`의 좌표·주소가 번호 매길 때 복사된다(`Object.assign`). 숙소 카드는 안내 탭 > 준비의 `#stay`.
- **탭 구조** — 하단 탭은 날짜 다섯 개 + **안내**(`more`) 여섯 칸이다. 안내 탭은 `#more` 안에 하위 탭 넷(`SUBS`: 추천 `recs` · 준비 `prep` · 교통 `move` · 날씨·비상 `wx`)을 두고, 섹션마다 `data-sub`로 어느 하위 탭에 속하는지 적는다. 날짜 탭에서는 `#more`가 통째로 숨는다 — **한 화면에 전부 늘어놓지 말 것**(스크롤만 길어서 보기 불편하다는 요청으로 바꿨다). 새 섹션을 만들면 반드시 `data-sub`를 달 것.
  - 다른 탭에 있는 카드로 가야 할 땐 `goTo(selector)`를 쓴다. 필요하면 안내 탭·해당 하위 탭으로 바꾼 뒤 스크롤한다. `scrollIntoView`를 직접 부르면 숨은 섹션이라 아무 일도 안 일어난다.
  - 하위 탭 줄은 `#more-bar`가 `position:sticky`다. **sticky는 키 큰 부모의 직계 자식이어야 붙는다.** 바를 감싸는 작은 래퍼에 sticky를 걸면 래퍼 높이만큼만 붙어 있다 사라진다(두 번 겪었다).
  - 선택한 하위 탭은 `tokyo-sub`에 저장된다.
- 기능: 하단 고정 날짜 탭, 상단 고정 날짜 바, **지도 위 1~5일차 칩**, Leaflet + OpenStreetMap 지도(종류 색 번호 마커, 숙소 마커, 순서대로 잇는 점선, `fitBounds`, 줌 컨트롤은 오른쪽 아래), 타일을 못 불러오면 SVG 간단 지도로 자동 전환(수동 전환 버튼도 있음), 장소별 구글 지도·길찾기 버튼, 하루 동선 전체 열기, 일본어 이름 병기와 크게 보기 다이얼로그, 지금·다음 강조(Asia/Tokyo 기준), 선택 일정 접기, 예약 체크리스트(localStorage)와 배지 연동, 일요일 출발 시각 역산, PWA 설치와 오프라인 캐시.
- **여행 중 날짜는 새벽 4시에 바뀐다(`DAYCUT_H`, `tripYmd()`).** 일정에 새벽 두세 시까지 여는 LP바가 있어서, 자정 기준으로 바꾸면 바에 앉아 있는데 다음 날이 열린다(한 번 겪었다). 탭 선택, 오늘 점, "n일차" 표시 모두 `tripYmd()`를 쓴다. 지금·다음 판정(`nowInfo()`)은 절대 시각이라 자정과 상관없다.
- **여행 기간에 앱을 열면 바로 지금(없으면 다음) 카드로 내려간다.** 여행 전·후에는 맨 위에서 시작한다. 탭을 옮기거나 앱으로 돌아올 때는 스크롤하지 않는다 — 읽던 자리를 뺏지 않게.
- **비행기** — 수요일 인천 18:00 출발 → 나리타 20:00 도착, 일요일 나리타 18:00 출발(2026-09-24 Henry가 "6시"라고 알려줌. 저녁 도착·일요일 긴자 일정과 맞아서 오후 6시로 읽었다. 편명은 모름).
- **일정 전체 재구성(2026-09-24, Henry가 자율권을 줌).** 원칙: 하루를 한 방향으로 돌고, 빠듯한 건 빼고, 비어 있던 끼니를 채운다.
  - **수:** 곤파치(23:00, 선택)는 뺐다. 22:30 체크인 뒤라 무리였고, 다음 날 9:30 시작이다.
  - **목:** 동쪽에서 시계 방향 — 호쿠사이 9:30(여는 시간) → 스카이트리 11:00 → ROUTE BOOKS 점심 12:30 → 서양미술관은 밖에서 건물만 10분(선택) → 도쿄국립박물관 13:45(15:30엔 나올 것) → **리쿠기엔 16:00(입장 16:30 마감, 해 질 녘)** → 이즈모 17:45 → Spincoaster 19:30. 예전엔 스카이트리(동) → 이케부쿠로(북서) → 요요기(서) 지그재그였고, 도쿄 일몰이 16:30쯤이라 "해질녘 17:30 스카이트리"는 이미 깜깜한 시간이었다. 직선거리 합계 29.1km → 23.1km.
  - **금:** 비어 있던 점심에 본디 카레 12:00. **아티존을 일요일에서 금요일 15:45로** 옮겼다(금요일은 20:00까지, 기쿠스시까지 걸어서 400m).
  - **일:** 아티존이 빠져 느긋해졌다. 츠타야 10:30 → **시세이도 파라 점심 11:30**(갤러리와 같은 건물) → 시세이도 갤러리 12:30(일요일 11:00 개관) → 모리오카 13:00 → 13:25 출발. 일요일 계산기는 장소별 `stay`(필요한 분, 기본 45)로 빠듯함을 판단한다 — 모리오카 15, 갤러리 30.
  - 토요일은 그대로 두었다(츠키지 → 롯폰기 → 아오야마 → 시부야 → 하츠다이 → 시모키타자와로 이미 한 방향).
- **카드 사이 이동 줄(`hopHTML`)** — 장소 카드 사이마다 직전 장소(첫 장소는 숙소)에서의 **직선거리**를 보여준다. 좌표로 계산한 값이라 사실이지만 실제 이동 거리는 아니니 "직선"이라는 말을 지우지 말 것. 4km(`FAR_KM`) 이상이면 "먼 이동" 상자로 강조하되 아침 숙소 출발은 빼고 센다. 확인된 경로(`leg`)는 카드 안이 아니라 이 줄에 붙는다. 동선이 멀어 보인다는 요청에서 나왔다(2026-09-24).
- **카드 밀도는 B안**(여백만 줄이고 메모는 다 보임, 버튼 이름 "길찾기"). 메모를 한 줄로 자르는 안은 흡연·현금 같은 경고를 숨겨서 쓰지 않았다. 비교한 세 안은 Figma 파일 "도쿄 여행 앱 — 디자인 안"(https://www.figma.com/design/oVAGZsn4FTiNloqrjK4IaX)에 있다.
- Figma 커넥터는 무료 요금제라 **읽기 호출이 한 달 20번**이다. 이 컨테이너에서는 mcp.figma.com으로 이미지 업로드가 막혀 있어서, 시안은 `use_figma`로 직접 그렸다.
- **내가 추가한 장소(`tokyo-mine`)** — 안내 > 추천 카드의 "일정에 넣기"로 날짜(목~일)·시간을 골라 넣는다. `{rid, day, t}` 배열로 저장하고 `indexStops()`가 원래 일정(`d.base`) 사이에 시간 순서로 끼워 넣은 뒤 번호·`_idx`를 다시 매긴다. 번호나 인덱스를 따로 매기는 코드를 새로 만들지 말고 `indexStops()`를 부를 것. 끼워 넣은 장소는 "내가 추가" 배지와 "일정에서 빼기"가 붙고, 기기에만 저장돼 CSV·캘린더 파일에는 들어가지 않는다. 그래서 추천(`RECS`)에도 `lat`/`lng`와 기본 자리 `slot`이 있다. 추천 좌표는 리쿠기엔(NAVITIME) 말고는 **대략값**이다.
- **리쿠기엔은 목요일 16:00, 진구가이엔 은행나무길은 토요일 14:00.** 리쿠기엔: 9~17시(입장 16:30까지), 300엔, 정문은 駒込역에서 걸어서 7분, 단풍철엔 2분 거리 染井門도 연다(도쿄도·문화구 기준). 은행나무길 좌표는 대략값이고 place_id도 없다.
- 한국어 조사는 `eunNeun()`으로 붙인다. "은(는)"을 화면에 쓰지 말 것.
- **도착 공항(`ARRIVE`, `applyArrival()`)** — 나리타 왕복으로 확정됐다(2026-09-24). 수요일 데이터의 기본값은 나리타 기준(22:30 체크인, 23:00 곤파치)이고, 수요일 화면에서 공항을 바꾸면 요약·체크인·곤파치 시각이 같이 바뀐다. 일요일 계산기 공항은 사용자가 일요일에서 직접 고르기 전까지(`tokyo-air-manual`) 도착 공항을 따라간다.
- **날씨(Open-Meteo, 키 없음)** — `forecast_days=16`으로 받아 여행 날짜만 골라 쓴다. `start_date`로 여행 날짜를 직접 요청하면 16일 밖일 때 오류가 나니 바꾸지 말 것. 받은 값은 `tokyo-wx`에 저장하고, 한 시간마다 새로 받는다. **사흘 넘은 예보는 숨기고, 지금 기온은 세 시간 넘으면 숨긴다** — 오래된 예보를 사실처럼 보여주지 않기 위해서다. Open-Meteo는 출처 표기가 조건이니 `Open-Meteo.com` 링크를 지우지 말 것. 예보가 없을 때는 기상청 평년값(11월 낮 16.7°C · 밤 8.8°C, 1991–2020)을 보여준다.
- **출발 전 준비(`PREP`)** — 예약 체크리스트와 같은 저장소를 쓴다. `go`가 있는 항목은 "바로 가기"로 해당 카드까지 간다(`goTo`).
- **긴급 연락처(`SOS`)** — `tel:` 링크. 대사관 번호는 외교부 주일본대사관 연락처 페이지 기준이고, 바뀌기 쉬우니 출발 전에 재확인하라고 화면에 적어 뒀다.
- **일본어 한마디(`PHRASES`)** — 보여주는 용도의 짧은 문장. 누르면 크게 보기 다이얼로그에 뜨고, 장소가 아니므로 지도 버튼은 숨긴다. 크게 보기의 `.big`은 한국어일 때 `keep-all`, 일본어일 때(`lang="ja"`) 일본어 줄바꿈 규칙을 쓴다. `keep-all`을 일본어에 걸면 띄어쓰기 없는 문장이 카드 밖으로 뻗는다(한 번 겪었다).
- **캘린더(`data/tokyo-trip.ics`)** — `tools/make-csv.mjs`가 CSV와 같이 만든다. 예약 있는 곳은 60분 전, 나머지는 30분 전 알림. 줄은 75바이트에서 접고(한글이 3바이트라 글자 수로 세면 안 된다), `DTSTAMP`는 고정값이라 다시 만들어도 내용이 안 바뀐다. 아이폰은 사이트에 올려진 실제 `.ics` 파일을 열어야 "모두 추가"가 뜨니 페이지 안에서 Blob으로 만들지 말 것. `DAYS`를 고치면 반드시 스크립트를 다시 돌릴 것.
- **공항 접근(`AIRPORTS[].routes`)** — 수요일 패널 아래 `arrivalHTML()`이 그린다. 공항을 고르면 수단별 소요시간·요금과 막차 안내가 바뀌고, 선택은 `tokyo-air-in`에 저장된다(일요일 출발용 `tokyo-air`와 별개). 착륙 시각은 수요일 첫 일정에서 가져오므로 그 시각을 바꾸면 경고 문구도 따라 바뀐다.
- **도쿄에서 움직이기(`TRANSIT`)** — 아래 섹션. 교통카드, 도쿄 서브웨이 티켓, 막차·택시.
- 요금·소요시간·막차는 전부 2026년 9월 22일 검색으로 확인한 값이고 화면에 출처를 달았다. **기억으로 숫자를 쓰지 말 것.** 바꿀 때는 출처를 새로 확인하고 확인 날짜도 같이 고친다.
- CSS 클래스 `.route`는 SVG 지도의 동선 폴리라인이 이미 쓰고 있다. 공항 경로는 `.aroute`다. 새 클래스를 만들 때 기존 이름과 겹치는지 먼저 확인할 것(한 번 겪었다).
- **추천(`RECS`)** — 안내 탭의 첫 하위 탭(`#sub-recs`). 일정 밖에서 가볼 만한 곳을 날짜별 끼워넣을 자리와 함께 보여준다. `renderRecs()`가 지도 없이 카드만 그린다.
  - **출처 없는 항목은 절대 넣지 말 것.** 항목마다 `src`(URL)·`srcn`(출처 이름)이 있어야 하고 화면에 확인 날짜와 함께 표시된다. "요즘 유행"은 기억으로 쓰면 틀린다 — 검색해서 확인하고 넣는다.
  - 시기가 걸린 정보(단풍 절정, 야간 라이트업 기간 등)는 이번 여행 날짜(11/18~22)에 해당하는지 `tip`에 분명히 적을 것. 예: 리쿠기엔 야간 관람은 11월 28일 시작이라 이번엔 못 본다.
- **지도 아래 장소 카드(`.mapcards`)가 이 화면의 중심이다.** 그날 장소가 가로로 늘어서고, 옆으로 넘기면 지도가 그 장소로 따라 움직이며 마커가 선택된다. 카드를 누르면 마커 팝업이 열린다. 선택 상태는 `setSel()` 하나가 관리한다 — 카드 `.on`, 마커 `.is-sel`, `setZIndexOffset`(겹친 마커 위로), 지도 `panTo`를 한꺼번에 처리하니 따로 손대지 말 것.
- 여행 기간이면 카드가 지금·다음 장소에서 시작한다.
- 일차 칩은 `요일 — 그날 요약`(`DAYS[].short`)이다. "1일차" 같은 번호로 되돌리지 말 것 — 어디로 가는 날인지가 보여야 고르기 쉽다. 가로 스크롤이고 오른쪽 56px은 줌 컨트롤 자리로 비워 둔다.
- 지도 `fitBounds`는 위(칩)·아래(카드)에 가려지는 만큼 비대칭 패딩(`FIT`)을 준다. `padding:[30,30]`으로 되돌리면 마커가 카드 뒤로 숨는다.
- **지도 ↔ 목록은 양방향이다.** 마커를 누르면 시간·이름·구글 지도·길찾기·일정 보기가 든 팝업이 열리고, 목록의 번호 노드를 누르면 지도가 그 장소로 이동하며 같은 팝업이 열린다. 둘 중 하나만 고치지 말 것.
- **장소 버튼 URL은 구글 공식 Maps URLs 형식만 쓴다**: `maps/search/?api=1&query=<이름>&query_place_id=<ID>`. `query_place_id`는 `query` 없이 보내면 안 된다. 이 조합이라야 아이폰·안드로이드 앱에서도 검색 결과가 아니라 그 장소 카드로 바로 열린다. **`maps/place/?q=place_id:…` 형식으로 바꾸지 말 것** — 데스크톱 웹에서만 먹고 앱은 저걸 검색어 텍스트로 읽어서 "검색결과 없음"이 뜬다(한 번 겪었다).
- **900px 이상에서는 2단**이다. 왼쪽에 지도가 `position:sticky`로 붙고 오른쪽에 그날 장소 목록이 선다. 구조는 `section.day > .dayhead / figure.map / .daylist`. 이 세 덩어리를 쪼개면 2단이 깨진다.
- `sw.js` — 설치할 때 HTML·Leaflet·Pretendard·아이콘·CSV를 캐시(`tokyo-shell-v*`). 지도 타일은 본 것만 `tokyo-tiles-v1`에 최대 900개, 폰트는 `tokyo-fonts-v1`에 담는다. 파일을 고쳐 배포할 땐 `VER`을 올릴 것.
- `vendor/`의 Leaflet 1.9.4는 CDN이 아니라 내려받아 둔 것이다(오프라인 캐시 때문). 업그레이드는 `dist/leaflet.js`, `dist/leaflet.css`, `dist/images/*`를 그대로 교체.
- **구글 장소 정보(Places API)**: 앱 안에서 키를 넣고 받아오면 평점·리뷰 수·분류·가격대·요일별 영업시간·사진이 카드에 붙는다.
  - 키는 localStorage `tokyo-gkey`, 받아온 값은 `tokyo-places`(`{at, v, byId}`)에 저장한다.
  - Places API (New) Place Details를 `key`·`fields` **쿼리 파라미터**로 부른다. 커스텀 헤더를 쓰면 CORS 프리플라이트가 생기니 헤더 방식으로 바꾸지 말 것.
  - 사진은 `…/media?skipHttpRedirect=true`로 `photoUri`만 받아 저장한다. 그래야 `<img>`에 키가 노출되지 않는다. 서비스 워커가 `googleusercontent.com` 응답을 `tokyo-photos-v1`에 캐시해서 오프라인에서도 보인다.
  - **구글 정책상 받아온 정보는 30일까지만 보관한다.** `PMAXAGE`가 그 기준이고, 지나면 표시를 멈추고 다시 받으라고 안내한다. 이 만료를 없애지 말 것.
  - 키가 400/401/403을 주면 바로 멈춘다(26번 두드리지 않는다).
  - **키 없이 넣는 길도 있다.** "물어볼 문장 복사" 버튼이 일정의 27곳 이름을 넣은 프롬프트를 만들어 주고, 클로드 채팅(구글 지도 커넥터가 붙어 있다)에서 받은 JSON을 붙여넣으면 `importPasted()`가 이름으로 맞춰 넣는다. 코드펜스와 앞뒤 설명은 알아서 걷어내고, 못 맞춘 이름은 화면에 알려준다. 사진은 이 방법으로 못 가져온다.
  - 저장 키는 `pkey(s) = s.id || "n:"+s.n`이다. 그래서 `place_id`가 없는 국립신미술관도 붙여넣기로는 들어간다. API 경로만 `place_id`를 요구한다.
  - `place_id`가 없는 곳(국립신미술관)은 API 경로에서 건너뛴다. 맞는 ID를 확인하면 `DAYS`에 넣을 것.
- `data/places.csv`는 Google My Maps 가져오기용, `data/tokyo-trip.ics`는 폰 캘린더용. `DAYS`를 바꿨으면 `node tools/make-csv.mjs`로 둘 다 다시 뽑을 것.

- **Vercel**: 저장소 루트의 `vercel.json`이 모든 경로를 `/tokyo-trip/`으로 rewrite한다. 그래서 앱이 사이트 루트(`/`)에서 열리고 서비스 워커 스코프도 `/`가 된다. 앱 파일을 다른 폴더로 옮기면 이 파일도 같이 고칠 것.
- **GitHub Pages**: `/저장소이름/tokyo-trip/` 하위 경로에서 그대로 열린다.
- 경로는 전부 상대 경로다. 절대 경로(`/icons/...`)를 쓰면 두 배포 중 하나가 깨진다.
- 파일을 고쳐 배포할 때마다 `sw.js` 맨 위 `VER`을 올릴 것.
- OSM 타일 정책상 대량 사전 다운로드는 금지다. "가기 전에" 섹션의 안내(와이파이에서 날짜별로 한 번씩 열어두기)를 유지할 것.
