# 도쿄 여행 일정 웹앱

Henry의 개인 여행용 모바일 웹페이지. 2026년 11월 18일(수)~22일(일), 아카사카 숙소 기준, 문화·예술 컨셉(미술관, 서점, 북카페, LP바). 여행 중 길 위에서 한 손으로 보는 용도가 1순위다. 사용자는 한국어를 쓴다. 모든 UI 문구는 한국어로.

## 현재 상태

- 빌드 과정 없음. 저장소의 이 폴더를 그대로 정적 호스팅하면 된다.
- `index.html` 한 파일에 CSS와 JS가 인라인으로 들어 있다. 디자인은 저장소의 `design-md/` 컬렉션에서 뽑아 왔다(아래 디자인 규칙 참고). 일정 데이터는 `<script>` 안 `/* DATA:START */ … /* DATA:END */` 블록의 `HOTEL`, `DAYS`, `CHECKS`, `AIRPORTS`, `LOOP` 다.
- 장소 필드: `t`(시간) `n`(이름) `ja`(일본어) `jaTodo`(일본어 미확인) `kc`(종류 키) `k`(종류 표시) `note` `need`(예약 배지) `ask`(확인 필요 배지) `needId`(예약 체크리스트 연결) `doneLabel` `ok`(현장 발권) `cash` `closed`(휴무) `close`(폐관·마감 시각) `tight`(마감 빠듯) `opt`(선택 일정) `leg`(직전 장소에서 오는 방법) `q`(지도 검색어) `id`(Google place_id) `lat` `lng`. 번호(`num`)와 인덱스(`_idx`)는 실행할 때 자동으로 붙는다.
- `kc` 값: `art` `book` `food` `bar` `market` `view` `hotel` `move`. 색은 `--k-*` 토큰, 아이콘은 `#i-*` 심볼.
- `HOTEL`은 아카사카역 근처 대략값이다. 정확한 숙소 위치는 아직 모름.
- 기능: 하단 고정 날짜 탭, 상단 고정 날짜 바, **지도 위 1~5일차 칩**, Leaflet + OpenStreetMap 지도(종류 색 번호 마커, 숙소 마커, 순서대로 잇는 점선, `fitBounds`, 줌 컨트롤은 오른쪽 아래), 타일을 못 불러오면 SVG 간단 지도로 자동 전환(수동 전환 버튼도 있음), 장소별 구글 지도·길찾기 버튼, 하루 동선 전체 열기, 일본어 이름 병기와 크게 보기 다이얼로그, 지금·다음 강조(Asia/Tokyo 기준), 선택 일정 접기, 예약 체크리스트(localStorage)와 배지 연동, 일요일 출발 시각 역산, PWA 설치와 오프라인 캐시.
- **추천 탭(`RECS`)** — 하단 탭 여섯 번째 칸. 일정 밖에서 가볼 만한 곳을 날짜별 끼워넣을 자리와 함께 보여준다. `renderRecs()`가 지도 없이 카드만 그린다.
  - **출처 없는 항목은 절대 넣지 말 것.** 항목마다 `src`(URL)·`srcn`(출처 이름)이 있어야 하고 화면에 확인 날짜와 함께 표시된다. "요즘 유행"은 기억으로 쓰면 틀린다 — 검색해서 확인하고 넣는다.
  - 시기가 걸린 정보(단풍 절정, 야간 라이트업 기간 등)는 이번 여행 날짜(11/18~22)에 해당하는지 `tip`에 분명히 적을 것. 예: 리쿠기엔 야간 관람은 11월 28일 시작이라 이번엔 못 본다.
- **지도 아래 장소 카드(`.mapcards`)가 이 화면의 중심이다.** 그날 장소가 가로로 늘어서고, 옆으로 넘기면 지도가 그 장소로 따라 움직이며 마커가 선택된다. 카드를 누르면 마커 팝업이 열린다. 선택 상태는 `setSel()` 하나가 관리한다 — 카드 `.on`, 마커 `.is-sel`, `setZIndexOffset`(겹친 마커 위로), 지도 `panTo`를 한꺼번에 처리하니 따로 손대지 말 것.
- 여행 기간이면 카드가 지금·다음 장소에서 시작한다.
- 일차 칩은 `요일 — 그날 요약`(`DAYS[].short`)이다. "1일차" 같은 번호로 되돌리지 말 것 — 어디로 가는 날인지가 보여야 고르기 쉽다. 가로 스크롤이고 오른쪽 56px은 줌 컨트롤 자리로 비워 둔다.
- 지도 `fitBounds`는 위(칩)·아래(카드)에 가려지는 만큼 비대칭 패딩(`FIT`)을 준다. `padding:[30,30]`으로 되돌리면 마커가 카드 뒤로 숨는다.
- **지도 ↔ 목록은 양방향이다.** 마커를 누르면 시간·이름·구글 지도·길찾기·일정 보기가 든 팝업이 열리고, 목록의 번호 노드를 누르면 지도가 그 장소로 이동하며 같은 팝업이 열린다. 둘 중 하나만 고치지 말 것.
- **장소 버튼 URL은 구글 공식 Maps URLs 형식만 쓴다**: `maps/search/?api=1&query=<이름>&query_place_id=<ID>`. `query_place_id`는 `query` 없이 보내면 안 된다. 이 조합이라야 아이폰·안드로이드 앱에서도 검색 결과가 아니라 그 장소 카드로 바로 열린다. **`maps/place/?q=place_id:…` 형식으로 바꾸지 말 것** — 데스크톱 웹에서만 먹고 앱은 저걸 검색어 텍스트로 읽어서 "검색결과 없음"이 뜬다(한 번 겪었다).
- **900px 이상에서는 2단**이다. 왼쪽에 지도가 `position:sticky`로 붙고 오른쪽에 그날 장소 목록이 선다. 구조는 `section.day > .dayhead / figure.map / .daylist`. 이 세 덩어리를 쪼개면 2단이 깨진다.
- `sw.js` — 설치할 때 HTML·Leaflet·아이콘·CSV를 캐시(`tokyo-shell-v1`). 지도 타일은 본 것만 `tokyo-tiles-v1`에 최대 900개, 폰트는 `tokyo-fonts-v1`에 담는다. 파일을 고쳐 배포할 땐 `VER`을 올릴 것.
- `vendor/`의 Leaflet 1.9.4는 CDN이 아니라 내려받아 둔 것이다(오프라인 캐시 때문). 업그레이드는 `dist/leaflet.js`, `dist/leaflet.css`, `dist/images/*`를 그대로 교체.
- **구글 장소 정보(Places API)**: 앱 안에서 키를 넣고 받아오면 평점·리뷰 수·분류·가격대·요일별 영업시간·사진이 카드에 붙는다.
  - 키는 localStorage `tokyo-gkey`, 받아온 값은 `tokyo-places`(`{at, v, byId}`)에 저장한다.
  - Places API (New) Place Details를 `key`·`fields` **쿼리 파라미터**로 부른다. 커스텀 헤더를 쓰면 CORS 프리플라이트가 생기니 헤더 방식으로 바꾸지 말 것.
  - 사진은 `…/media?skipHttpRedirect=true`로 `photoUri`만 받아 저장한다. 그래야 `<img>`에 키가 노출되지 않는다. 서비스 워커가 `googleusercontent.com` 응답을 `tokyo-photos-v1`에 캐시해서 오프라인에서도 보인다.
  - **구글 정책상 받아온 정보는 30일까지만 보관한다.** `PMAXAGE`가 그 기준이고, 지나면 표시를 멈추고 다시 받으라고 안내한다. 이 만료를 없애지 말 것.
  - 키가 400/401/403을 주면 바로 멈춘다(26번 두드리지 않는다).
  - `place_id`가 없는 곳(국립신미술관)은 건너뛴다. 맞는 ID를 확인하면 `DAYS`에 넣을 것.
- `data/places.csv`는 Google My Maps 가져오기용. `DAYS`를 바꿨으면 `node tools/make-csv.mjs`로 다시 뽑을 것.

## 할 일

### 남은 것

- **구간 이동 정보(`leg`)** — 검증된 두 구간만 채워져 있다. 토요일 츠키지 → 국립신미술관(히비야선 직통), 국립신미술관 → 네즈(치요다선 노기자카 → 오모테산도). 나머지는 비워 두고 길찾기 버튼만 보여준다. **추측으로 채우지 말 것.** 확인해서 채울 때는 `{line, from, to, note, v:true}` 형식으로, 검증 전이면 `v`를 빼면 "(확인 전)"이 붙는다.
- **기쿠스시 일본어 표기** — `jaTodo:true`로 두었다. Google 지도에서 확인하고 `ja`로 바꿀 것.
- **입장료와 하루 예산** — 공식 사이트에서 확인한 값만, 확인 날짜와 함께 넣을 것. 아직 아무것도 넣지 않았다. (Places API의 `priceLevel`은 가격대 기호(¥¥)일 뿐 입장료가 아니다.)
- **구글 지도 타일** — 지금은 OpenStreetMap이라 지명이 일본어다. 한국어 지명과 구글 스타일을 쓰려면 Maps JavaScript API 키로 두 번째 지도 구현이 필요하고, 구글 타일은 캐시가 금지라 오프라인이 깨진다. 넣는다면 키가 있을 때만 구글, 없거나 오프라인이면 지금의 Leaflet로 떨어지는 3단 구조로 할 것.
- **Places API 실제 키 테스트** — 코드는 잘못된 키로 오류 경로만 확인했다. 진짜 키로 한 번 받아 보고, 필드 이름이나 한국어 표기가 예상과 다르면 `placeRow`를 손볼 것.
- **숙소 정확한 위치** — 알게 되면 `HOTEL`의 `lat`/`lng`/`n`을 고치고 CSV를 다시 뽑을 것.
- **일요일 비행기 시간** — 페이지의 계산기에 직접 입력하는 방식이라 코드를 고칠 필요는 없다. 다만 긴자 → 공항 이동 시간(하네다 45분, 나리타 80분)은 **추정값**이고 화면에도 그렇게 적어 두었다. 실제 경로로 확인되면 `AIRPORTS`의 `mins`를 고칠 것.
- **스카이트리 구간** — 원래 note에 있던 "두 정거장"은 검증되지 않아 지웠다. 확인되면 `leg`로 넣을 것.

## 디자인 규칙 (유지)

저장소 루트의 `design-md/` 세 문서에서 원칙을 가져왔다. 새 화면을 붙일 때도 이 세 가지를 따른다.

**The Verge (`design-md/theverge`) — 구조와 타이포**
- 일정은 StoryStream 타임라인이다. 왼쪽 레일에 모노 시각 + 종류색 노드, 오른쪽에 `--r-card`(20px) 알약 모서리 카드. 카드 사이 간격 12px, 레일은 1px 실선으로 계속 이어진다.
- "속삭임 vs 외침": 거대한 Hahmlet 제목(`h1` 최대 76px, 자간 -0.03em) 위에 자간 벌린 얇은 모노 아이브로. 이 대비가 이 화면의 지문이다.
- **액센트 블록은 한 화면에 하나뿐이다.** 은행잎 꽉 찬 카드는 `.stop.now`(지금 있어야 할 곳)만 쓴다. `.stop.next`는 테두리와 7% 틴트까지만. 이 규칙을 깨면 강조가 상쇄된다.
- 그림자 없음. 깊이는 1px 헤어라인과 표면색 변화로만 만든다.
- 호버는 색만 바뀐다. 들어올리거나 확대하지 않는다. 150ms.

**Linear (`design-md/linear.app`) — 밀도**
- 4px 배수 간격 토큰 `--s1`~`--s8`. 카드 안쪽 16px, 섹션 사이 48px.
- 헤어라인 패널, 액센트는 은행잎 하나. 종류색(`--k-*`)은 노드·아이콘·카드 틴트(`--tint`)에만 쓰고 은행잎보다 튀면 안 된다.

**Apple (`design-md/apple`) — 여백과 읽는 속도**
- 본문 17px. 스캔이 아니라 읽는 속도를 만든다. 카드 안 메모만 15px.
- 히어로 위 64px, 아래 48px의 공기.
- 지도는 이 화면의 주인공이라 480px 미만에서 좌우 여백을 깨고 풀블리드로 나간다.

**계속 지키는 것**
- 늦가을 도쿄 은행나무 컨셉. 색 토큰은 `:root`에 있는 그대로: 종이 `#ECEEF1`, 표면 `#F7F8FA`, 먹색 `#1E2B4A`, 보조 `#5C6680`, 선 `#C9CED8`, 은행잎 `#E8B620`, 소나무 `#2F5D50`. 다크모드는 `#141A2B` 계열.
- 글꼴: 제목 Hahmlet(세리프), 본문 IBM Plex Sans KR, **숫자·날짜·시각만** JetBrains Mono. 모노 스택에는 반드시 한글 폴백을 남겨 둘 것 — 한글이 고정폭으로 떨어지면 바로 망가진다.
- **대문자 라벨 금지.** Verge의 모노 대문자 라벨은 가져오지 않았다. 모노는 숫자에만.
- 하지 말 것: 제목 한 단어만 강조, 모든 섹션에 등장 애니메이션, 똑같은 카드 반복, 링크 끝에 화살표.
- 모바일 390px 기준 먼저, 최대 폭 680px. 다크모드, `prefers-reduced-motion`, 키보드 포커스 유지. 터치 타깃 44px.
- `color-mix`를 쓸 땐 바로 앞 줄에 단색 폴백을 함께 적을 것(구형 사파리).
- 지나간 일정(`.stop.past`)은 메모·이동정보·버튼·사진을 접는다. 이미 다녀온 곳에 길찾기는 필요 없다.
- 카드 머리는 `.chead > .cmain + .thumb` 플렉스다. 썸네일을 `float`로 되돌리지 말 것 — `.namebtn`이 버튼이라 BFC를 만들어 float 옆에 서지 못하고 아래로 밀린다.
- 지도 위 일차 칩은 그림자 없이 단색 표면 + 헤어라인으로 타일과 구분한다.
- 하단 탭은 알약 여섯 개가 아니라 **세그먼티드 컨트롤 하나**다(바깥에 헤어라인 하나, 안쪽 칸은 테두리 없음). 칸마다 테두리를 두르면 바로 투박해진다.
- 히어로의 통계 줄과 하루 메타 줄은 **한 줄로 유지한다**(`flex-wrap:nowrap` + 가로 스크롤). 줄바꿈되면 구분선이 문단 앞에 매달려 지저분해진다.
- 문구는 짧게, 존댓말, 여행자 입장에서.

## 배포

- 빌드 없이 이 폴더를 그대로 서빙한다. 배포는 `main` 한 브랜치만 본다.
- **Vercel**: 저장소 루트의 `vercel.json`이 모든 경로를 `/tokyo-trip/`으로 rewrite한다. 그래서 앱이 사이트 루트(`/`)에서 열리고 서비스 워커 스코프도 `/`가 된다. 앱 파일을 다른 폴더로 옮기면 이 파일도 같이 고칠 것.
- **GitHub Pages**: `/저장소이름/tokyo-trip/` 하위 경로에서 그대로 열린다.
- 경로는 전부 상대 경로다. 절대 경로(`/icons/...`)를 쓰면 두 배포 중 하나가 깨진다.
- 파일을 고쳐 배포할 때마다 `sw.js` 맨 위 `VER`을 올릴 것.
- OSM 타일 정책상 대량 사전 다운로드는 금지다. "가기 전에" 섹션의 안내(와이파이에서 날짜별로 한 번씩 열어두기)를 유지할 것.
